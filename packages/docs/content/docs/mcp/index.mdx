### Errors [#errors]

A failed call has `isError: true` and no `structuredContent`. `content[0]` says what happened and the next call to make; `content[1]` is the [error envelope](/errors) as JSON text, and `_meta["ai.fortrip/error"]` carries it too. Input is checked by Fortrip, not by the client's SDK, so an invalid argument answers `invalid_request` with the field at fault.

## Server instructions [#instructions]

On connect the server returns `instructions`, a short form of the agent guide: when to use Fortrip, the call order and what to show the user before they pay. Keep them in your agent's system prompt. The full agent guide is what `fortrip guide` prints. `get_planning_guide` returns a separate guide, for requests that are more than one hotel for fixed dates.

## Timeouts and retries [#retries]

- Creating an order or paying can take a couple of minutes. Give `book_hotel` and `pay_order` a timeout of at least three minutes.
- After a `book_hotel` timeout, call it again with the same details: it is [safe to send again](/api#retries).

## Connecting your own agent [#own-agent]

- Sign-in follows the MCP authorization spec: OAuth 2.1 with PKCE. The authorization server's metadata is at <Fact path="OAUTH_METADATA_URL" />.
- Dynamic client registration is supported, so your client can register itself.
- Each end user signs in once, with their own Fortrip account. Their orders and payment links belong to that account.
