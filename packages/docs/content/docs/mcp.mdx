## Endpoint [#endpoint]

<pre><code><Fact path="MCP_SERVER_URL" /></code></pre>

Streamable HTTP with OAuth sign-in to a Fortrip account; no API key. Clients that only launch local commands can run [`npx -y fortrip mcp`](/cli/mcp) instead, a stdio bridge to this server. Setup for each client is in [Installation](/install#remote-mcp).

Each tool takes the same input as its [HTTP endpoint](/api#endpoints).

### Annotations [#annotations]

<ToolAnnotations />

`create_order`, `cancel_order` and `pay_order` are marked destructive: a client that confirms destructive calls asks the user before each one. Each tool's annotations also carry its title, as `annotations.title`.

## What a tool returns [#results]

A result is text only. `content` holds exactly one block, of type `text`: the whole answer, written for the model, with one line per hotel, offer or order and its ids. There is no `structuredContent`, and no tool declares an `outputSchema`.

### JSON for your code [#json]

When your code needs the object, read it over the [HTTP API](/api), where each tool has an endpoint that answers JSON for the same input, or run the CLI command with `--json`. The [response schemas](/schemas) list every field.

### Text from hotels [#third-party-text]

Hotel, room and place names, addresses, descriptions and policies are the hotel's words, and guest names, the contact and special requests are the caller's. A short one is in double quotes, as a JSON string: `Hotel: "Lakeside Garden Resort"`. A longer one is a quoted block, labelled as information from the hotel and not instructions. Show a name to the user without its quotes.

### Errors [#errors]

A failed call has `isError: true` and one text block. The text gives the error's code, what happened, whether a retry can help and the next call to make. `_meta["ai.fortrip/error"]` carries the [error envelope](/errors) for your code. Input is checked by Fortrip, not by the client's SDK, so an invalid argument answers `invalid_request` this way, with the field at fault.

## Server instructions [#instructions]

On connect the server returns `instructions`, a short form of the agent guide: when to use Fortrip, the call order and what to show the user before they pay. Keep them in your agent's system prompt. `serverInfo` carries the server's `name`, `title`, `description`, `websiteUrl` and `icons`.

## Timeouts and retries [#retries]

- Creating an order or paying can take a couple of minutes. Give `create_order` and `pay_order` a timeout of at least three minutes.
- After a `create_order` timeout, call it again with the same details.
- After a `pay_order` timeout, <PayAfterTimeout />

What each call answers when sent again, and which errors to retry, are in [Retries and idempotency](/api#retries).

## Connecting your own agent [#own-agent]

- Sign-in follows the MCP authorization spec: OAuth 2.1 with PKCE. The authorization server's metadata is at <Fact path="OAUTH_METADATA_URL" />.
- Dynamic client registration is supported, so your client can register itself.
- Each end user signs in with their own Fortrip account. Their orders and payment links belong to that account.
