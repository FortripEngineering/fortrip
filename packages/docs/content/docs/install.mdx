## Choosing a setup [#choosing]

Coding agents (Claude Code, Codex and others) → [the skill](#skill). Instead of the skill, Claude Code can use [the plugin](#claude-code) and Codex [MCP](#codex). Chat apps → the remote MCP connector ([claude.ai](#claude-ai), [Claude Desktop](#claude-desktop), [ChatGPT](#chatgpt)). Install one per agent, not several. Each uses the same Fortrip account and returns the same data.

## Agent skill [#skill]

For Codex, Claude Code, Muse, WorkBuddy and other agents that use skills and can run shell commands.

<pre><code><Fact path="SKILL_INSTALL_COMMAND" /></code></pre>

`npx skills add` runs the open-source skills installer. It finds the agents on your machine, asks which ones to add the skill to, and writes it to their skills folders in the current project; add `-g` to install it for every project.

The skill carries the agent guide: when to use Fortrip, the call order, how to sign in, and what to show the user before they pay. Your agent runs the CLI with `npx -y fortrip@latest`, so it may ask your permission to run those commands. `fortrip guide` prints the same guide.

## CLI [#cli]

Needs Node.js <Fact path="CLI_NODE_MAJOR" /> or newer. Run it with `npx`, or install it globally:

```sh
npm install -g fortrip
```

The package and the command are both `fortrip`. Its source is at <Fact path="REPOSITORY_URL" />. See the [CLI reference](/cli).

## Local MCP [#local-mcp]

For clients that launch local commands. The CLI runs a stdio server that forwards to the hosted server, so there is nothing else to install. It uses the CLI's sign-in, so run `npx -y fortrip login` first. Then add it to your client:

```json
{
  "mcpServers": {
    "fortrip": {
      "command": "npx",
      "args": ["-y", "fortrip", "mcp"]
    }
  }
}
```

Configure either the remote or the local server in a client, not both. See [fortrip mcp](/cli/mcp).

## Authentication [#authentication]

| Connection | How it signs in |
| --- | --- |
| Skill, CLI, local MCP | `npx fortrip login` prints a link and a code; open the link, sign in to Fortrip and approve. You stay signed in until `npx fortrip logout`. In a remote agent environment or a CI run, set `FORTRIP_TOKEN` to an access token instead; see [Environment](/cli#environment). |
| Remote MCP | Your client opens a Fortrip sign-in page and you approve access. |
| HTTP API | OAuth access tokens, sent as `Authorization: Bearer`. See [HTTP API](/api#authentication). |

When a CLI command needs a sign-in it doesn't wait: it exits with [code <Fact path="CLI_EXIT.unauthenticated" />](/errors#exit-codes) and prints a `loginUrl` and a `userCode` (for a rejected `FORTRIP_TOKEN`, its `tokenSource` instead). An agent can give both to the user and run the command again once they have approved.

To disconnect, remove the connector in your client; the CLI signs out with `npx fortrip logout`.
