## Base URL [#base-url]

<pre><code><Fact path="API_BASE_URL" /></code></pre>

JSON over HTTPS. Reads are `GET` with query parameters; everything else is `POST` with a JSON body. A field the input doesn't define is refused with `invalid_request`; a known field sent at the wrong depth is answered with the path it belongs at. There is no CORS: call the API from a server or a script, not from a web page. To try it, start with the [API quickstart](/api-quickstart).

## Authentication [#authentication]

Every endpoint except <code><Fact path="ROUTES.authConfig" /></code> needs an API key or an OAuth access token, sent as `Authorization: Bearer <token>`. Cookies are not accepted.

| For | Use | It lasts |
| --- | --- | --- |
| Your own scripts and server | An [API key](#api-keys) | Until you revoke it |
| A CLI or script that signs a user in, or before you have a key | The [device flow](#device-flow) | A short-lived access token, renewed with a refresh token |

A key or a token acts as one Fortrip account: the orders, payment links and rate limits are that account's. An API key is for your own account only: never share it with other people. To build an app that other people use with their own Fortrip accounts, email <Fact path="SUPPORT_EMAIL" />. There are no service accounts.

### API keys [#api-keys]

An API key starts with `ak_`. To get API keys, email <Fact path="SUPPORT_EMAIL" /> from your Fortrip account's address. Once they are on, your account's profile on the Fortrip website (Manage account) has an **API keys** tab, where you create and revoke keys.

- A key acts as the account that made it, with the scopes `profile email`, and needs no refresh.
- A key can do everything the account can, cancelling and paying orders included. Keep it on a server, never in a web page or an app you ship.
- A revoked key, or any key of an account whose API keys were turned off, answers `401 unauthenticated`. Turning an account's API keys back on makes its keys that weren't revoked work again.
- Keys work on the HTTP API only. The [MCP server](/mcp) doesn't take them: MCP clients sign in with OAuth.

### Device flow [#device-flow]

The standard OAuth device authorization flow (RFC 8628). The [API quickstart](/api-quickstart#sign-in) runs it in curl, TypeScript and Python.

1. <code><Fact path="ROUTES.authConfig" /></code> returns `clientId`, `scopes`, `deviceAuthorizationEndpoint`, `tokenEndpoint` and `revocationEndpoint`.
2. Post `client_id` and `scope` to `deviceAuthorizationEndpoint`, show the user its `verification_uri_complete`, then poll `tokenEndpoint` every `interval` seconds until the user approves. Request `offline_access`, which `scopes` includes, to get a refresh token.
3. The access token is short-lived: its lifetime, in seconds, is the token response's `expires_in`. Refresh it at `tokenEndpoint` with `grant_type=refresh_token`. Every refresh returns a new refresh token: keep only the newest, because reusing an old one revokes the whole grant and the user has to sign in again.
4. To sign out, revoke the refresh token at `revocationEndpoint`, with your `client_id`.

## Conventions [#conventions]

- Fields are camelCase. Ids are opaque strings with a prefix: `htl_` hotels, `off_` offers, `ord_` orders and `plc_` places. Pass them back exactly as received.
- Instants end in `At` and are RFC 3339 in UTC. Dates are `yyyy-MM-dd` in the hotel's calendar, and times of day `HH:mm` in the hotel's time zone, its IANA `timeZone`.
- Coordinates are `{ lat, lng }` in WGS84; distances are in meters.
- Names with an English and a Chinese form are `name`, in the requested `locale`, plus `names: { en, zh }`. Other text from the catalogue is `{ text, locale }`, with `locale` `null` when unknown. Messages the API writes are in English.
- **Unknown is not no.** A list or flag the source didn't state is `null`, or comes with `known`, `listed`, `disclosure` or `status` saying so. An amenity that isn't listed may still exist.
- **Read responses tolerantly.** Objects can gain fields, enums can gain values and unions can gain branches: don't fail on one you don't know.

### Money [#money]

- Money is `{ amount: "132.40", currency: "USD" }`. The amount is a decimal string: read it as a decimal, not a float.
- Prices are in the request's `currency` (USD, the default, or <OtherCurrencies />). Money you send back, a payment's `total` or a cancellation's `maximumPenalty`, is copied from the order exactly as returned.
- An order is charged its `total`, in the currency that `total` names. Orders made through the API are charged in the currency of their offers; orders made on the Fortrip website, which the order list includes, may be in another currency.
- Fees paid at the property, `payAtProperty`, come on top of the total, in the property's currency. <Fact path="GUIDE_SENTENCES.adaptivePricing" />

## Headers [#headers]

| Header | Meaning |
| --- | --- |
| `Request-Id` | On every response, and as `requestId` in an error. Quote it to support. |
| `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` | On every response a rate limit counted: the limit per minute, what is left, and seconds until the window resets. See [rate limits](/errors#rate-limits). |
| `Retry-After` | On every retryable error: seconds to wait. The envelope's `retryAfterSeconds` says the same. |
| <code><Fact path="ORDER_HTTP.replayedHeader" /></code> | `true` when <code><Fact path="ROUTES.create_order" /></code> answers an order it already created for the same details. |

## Pagination [#pagination]

Search results and the order list are pages, with `data` and `nextCursor`. Pass `nextCursor` back as `cursor`; a next page of a search takes only `cursor` and, optionally, `limit`. `nextCursor` is `null` on the last page. An expired or edited cursor answers `400 cursor_invalid`.

Live offers are not a page: one call answers a bounded number of offers, grouped by hotel. [The offers budget](/errors#offers-budget) says how many and how to see more.

## Polling [#polling]

There are no webhooks. After you give the user the payment link, read the order with <code><Fact path="ROUTES.get_order" /></code> when the user says they have paid, or every few seconds while they are paying, and keep reading while it is `confirming`. Each read counts against the `orders_read` limit of <Fact path="RATE_LIMITS.orders_read.limit" /> calls a minute. How long the hotel may take is in the offer's `confirmation`: `instant`, or `on_request` within `withinMinutes`.

## Orders [#orders]

- <code><Fact path="ROUTES.create_order" /></code> answers <Fact path="ORDER_HTTP.createdStatus" /> with an order `awaiting_payment`, and <Fact path="ORDER_HTTP.replayedStatus" /> with <code><Fact path="ORDER_HTTP.replayedHeader" />: true</code> when the same details are sent again.
- <code><Fact path="ROUTES.pay_order" /></code> takes `sharedPaymentToken`, the token the user approved for the order, and `total`, the order's `total` exactly as returned. Both are required.

The flow, the ways to pay, the order statuses, and cancelling and closing are in [Orders and payment](/payments).
