The contract, [`@fortrip/agent-contract`](https://www.npmjs.com/package/@fortrip/agent-contract), and the CLI, [`fortrip`](https://www.npmjs.com/package/fortrip), share one version number.

## 6.5.1

Released 2026-11-26.

The schemas, the tools, the commands and the errors keep their shape. The change is to the text that agents read.

- An order started on the Fortrip website can await payment with no payment link: `payment.url` is `null` and `cancel.blockedBy` is `website_checkout`. The user finishes paying in the browser tab they started it in, or the order expires unpaid at `payment.expiresAt`. The order's text, the description of `payment.url` and the guide say so, and that reading the order again gives no link; they no longer call it a payment being processed.
- The text of `payment_method_unavailable` with reason `token_not_offered` sends the reader to the order's Payment link line for how the order is paid, since such an order may have no link.

## 6.5.0

Released 2026-11-26.

- The assistant can ask for a price match: when the user saw an offer's stay cheaper on another site, `request_price_match` (`POST /v1/price-matches`, `fortrip hotels price-match`) sends the offer and the site's name, with the link to the page where the user saw the price (the assistant asks the user for it; a link on a comparison site that leads to the booking site counts) and the total they saw if they gave one. Fortrip checks that one site, which can take up to ten minutes, so the answer comes at once: with a `claimId`, a progress link to share with the user and the number of seconds to wait before reading it again, or declined with a `reason`, in which case the answer may have no `claimId`.
- `get_price_match` (`GET /v1/price-matches/{claimId}`, `fortrip hotels price-match-status`) reads where the check stands: `checking`, `matched`, `partial` or `declined`. A `matched` answer carries a new offer at the matched price, with its total, saving and expiry (the comparison counts what is paid at the hotel, so the new total is the other site's total less Fortrip's own fees paid there, `ourFeesAtProperty`; when those fees can't all be counted, because one is not known or is in another currency, `propertyFeeLeftOut` is `true` and the comparison leaves them out), to order with `create_order` like any offer. A `partial` answer carries a new offer at the lowest price a price match can give, short of the other site's price. A `declined` answer says why, and the original offer stays as it was.
- A price match is not a guarantee. Only the site the user named, or the booking site their link leads to, is checked, a price match is limited in how far it lowers a price, and the answer can be that no match is available right now. Price matches cover USD offers of one room for now.
- `request_price_match` and `get_price_match` are in an account's MCP tool list only while price match is open to that account; for any other account, a request that would start a new check is declined with `unavailable`.
- Price-match requests and reads share one rate limit, listed with the others under [Errors](/errors#rate-limits).
- `request_price_match` is not marked idempotent: the same call answers the same price match while its check runs or its result stands, and a new link or a check that ended unfinished starts a new one.
- While a check runs, the answer tells an assistant that cannot wait to give the user the progress page and ask them to ask again in a few minutes, and not to read the price match again sooner than `checkAgainAfterSeconds`.

### Package

- New tools `request_price_match` and `get_price_match`, with the inputs `requestPriceMatchInput` and `getPriceMatchInput`, the `priceMatch` response and its `PriceMatch` type, and the `price_match` rate limit.
- New CLI commands `fortrip hotels price-match` and `fortrip hotels price-match-status`.
- `renderError` takes `options.tool`, the tool that answered the error: `not_found` and `offer_expired` are then worded for the price-match tools.

## 6.4.0

Released 2026-11-17.

- The hosted MCP server offers `pay_order` through the CLI's `fortrip mcp` alone. Every other client has the other seven tools, and the user pays on the page the payment link opens. `POST /v1/orders/{orderId}/pay` and `fortrip orders pay` are as before.
- Each MCP tool's annotations carry its title, as `annotations.title`.

### Package

- `ToolSpec.annotations` has a `title`, the tool's own `title`.

## 6.3.0

Released 2026-11-17.

- The hosted MCP server no longer offers `pay_order` to Claude or Claude Code.
- The Claude plugin's skill no longer describes payment by token.

### Package

- `renderGuide("claude-skill", topic, { tokenPay: false })` renders the Claude skill's guide without payment by token.

## 6.2.0

Released 2026-11-16.

The schemas, the tools, the commands and the errors keep their shape. The change is to the text that agents read.

- Each tool's description starts by saying when the tool is used.
- `search_hotels` says its destination is the place the user asked for, never a location they did not give.
- The hosted MCP server's error text ends with its request id only for an `internal` error. Every error still carries the id in `_meta["ai.fortrip/error"]`.

### Package

- `renderError(envelope, status, surface, { tokenPay: false })` words an error for a client not offered payment by token.

## 6.1.0

Released 2026-11-16.

- The hosted MCP server no longer offers `pay_order` to ChatGPT.

### Package

- A `tokenPay: false` option on `renderGuide`, `renderToolResult` and `toolsFor`, for a client not offered payment by token.

## 6.0.1

Released 2026-11-16.

The schemas, the tools, the commands and the errors keep their shape. The change is to the text that agents read.

- An offers answer says when a term is unknown for only some of a hotel's offers.
- The support address is `support@fortrip.ai`.
- The guide says an order can't be changed: it can only be cancelled under its terms and ordered again.

## 6.0.0

Released 2026-11-14.

A major release, with no compatibility with earlier versions. Update the CLI with `npm install -g fortrip@latest`.

- **MCP results are text only.** A result's `content` is one text block, written for the model, and an error's envelope is in `_meta["ai.fortrip/error"]`. Code that needs the object calls the HTTP API or runs the CLI with `--json`. See [What a tool returns](/mcp#results).
- **Orders are created with `create_order`** (`fortrip orders create`), and the contact has one `name`.
- **Cancelling names its mode.** `cancel_order` takes exactly one of `maximumPenalty`, to cancel a paid order, and `close: true`, to close an unpaid one. A closed order has its own status, `closed`.
- **Paying takes a token and the total.** `pay_order` takes `sharedPaymentToken` and `total`. An agent no longer opens an Alipay or WeChat Pay payment: the user pays that way on the order's payment page.
- **Each concept has one name.** `total`, `roomType`, `meals` and `payAtProperty` have the same name and shape on an offer and on an order. An order says how it can be paid in `payment.tokenRequest`, what can be done to it in `cancel`, why it failed in `failure`, and what a cancellation kept and returned in `cancelled`.
- **An offers call answers a bounded number of offers.** See [the offers budget](/errors#offers-budget).
- **Errors say more.** `invalid_request` names where a misplaced field belongs, a guest name the hotel's booking system would refuse is refused before an order is made, and a CLI that is a major version behind is told to update with `client_outdated`.

### Package

- `renderToolResult` returns the whole text of a result, its closing rules included: send it as the one text block and add nothing. `renderError` builds its text from the error's `code` and `details`.

## Before 6.0
