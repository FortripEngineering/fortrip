The contract, [`@fortrip/agent-contract`](https://www.npmjs.com/package/@fortrip/agent-contract), and the CLI, [`fortrip`](https://www.npmjs.com/package/fortrip), share one version number. Each entry lists breaking changes first, then what is new, then how to migrate. The values in an entry are the ones that release had.

## 6.0.0

Not released yet.

A major release, with no compatibility with 5.x. An MCP tool answers in text only, `book_hotel` is `create_order`, and each concept has one name and one place across requests, answers and errors. An agent no longer opens an Alipay or WeChat Pay payment: the user pays that way on the order's payment page.

### 6.0.0-rc.1

What changed since 6.0.0-rc.0: the text a model reads and the messages of refused requests. No request or answer changes shape.

- **A search's estimates are for the searched dates.** The search text says so, and that what may be days old is when the price was read.
- **A failed order says what became of the money.** A `Money:` line after "Why it failed" says it as the payment status does: charged and refunded, a refund under way, held and released, or nothing paid. A `hotel_refused` order tells the model to give the user the support address and the order's reference now, before any new order.
- **Each currency sentence names the way of paying it is about.** The order's Total line says the card may pay in its local currency on the payment link's page; the pay paragraph says a payment by token with `pay_order` is charged in USD.
- **After `offer_changed`, the reply ends by asking.** The error's text tells the model to end its reply by asking whether to order the new offer, and to wait for the answer.
- **The consent rules are in the order's text only.** The descriptions of `cancel_order` and `pay_order` no longer repeat them; the cancel and pay paragraphs of the order's text still carry them.
- **`create_order` says how many rooms and guests to send.** `items[].hotel.rooms` is one entry per room of the offer, not one per adult, and `guests` lists only the guests the user named. A blank guest name, or a room without guests, is refused with what to send instead.
- **Two refusals say what to send.** A room without `childrenAges` is told to send an empty list when it has no children, and `get_hotel`'s `include` sent as a list is told it takes the value itself.

### Breaking changes

What an integration must change, most urgent first. The [migration table](#v6-migration) lists every name.

- **MCP results are text only.** A result's `content` is one text block, the whole answer written for the model. `structuredContent` is gone, and no tool declares an `outputSchema`. A client that read `structuredContent` reads the text instead; code that needs the object calls the HTTP API or runs the CLI with `--json`. See [What a tool returns](/mcp#results).
- **An MCP error is one text block.** The error envelope is no longer a second block of JSON text: it is in `_meta["ai.fortrip/error"]`.
- **`book_hotel` is `create_order`**, and the CLI's `fortrip hotels book` is `fortrip orders create`. The HTTP path, `POST /v1/orders`, is unchanged. `create_order` and `pay_order` are now marked destructive, as `cancel_order` was, so a client that confirms destructive calls asks the user before each.
- **The contact has one name.** Send `contact.name` in place of `contact.firstName` and `contact.lastName` (`--name` in the CLI).
- **Cancelling names its mode.** `cancel_order` takes exactly one of `maximumPenalty`, to cancel a paid order, and `close: true`, to close an unpaid one. An `orderId` alone is refused. A mode that doesn't fit the order answers `order_not_cancellable` with the order's `cancel` as it is now; `close` on an order paid meanwhile is refused that way, where 5.x answered the paid order.
- **Paying takes a token and the total.** `pay_order` takes `sharedPaymentToken` and `total`, both required. Its `payment` object and its `method` are removed, and with `method` the Alipay and WeChat Pay payment an agent could open. The user still pays with either on the page `payment.url` opens.
- **An order says how it can be paid and cancelled in new fields.** `payment.methods` is `payment.tokenRequest` (what a token is requested with), `price.total` is `total`, `payment.chargeCurrency` is `total.currency`, and `cancel.available` and `cancel.reason` are `cancel.action` and `cancel.blockedBy`.
- **A closed order has its own status.** An unpaid order closed at the caller's request is `closed`; `expired` now means only that the time to pay ran out.
- **`pay_order` takes a total in USD only.** A token pays a USD order; a `total` in CNY is `invalid_request`.
- **An offer is flat.** `hotel.room`, `hotel.roomCount`, `hotel.meals`, `price.total` and `price.payAtProperty` are `roomType`, `roomCount`, `meals`, `total` and `payAtProperty` on the offer itself. `price.perNightAllRooms` is replaced by `perRoomNight`, which also divides by the rooms.
- **An order's room type and meals are per room**, on each entry of `items[].hotel.rooms`, not on the hotel item.
- **Search and hotel answers are renamed** in several places: a hit's `price` is `indicativePrice`, `text` is a string, `currencyHint` is always present and `null` when there is none, a locality's `total` is `localityTotal`, and a hotel's `rooms` is `roomTypes`, asked for with `include=roomTypes`.
- **Errors:** `payment_total_changed` is `payment_total_mismatch`, an error's `param` is `pointer`, and the `details` of `order_not_cancellable`, `rate_limited` and `destination_not_found` are renamed.
- **An offers call answers a bounded number of offers.** `limitPerHotel` has no fixed default: without it a call answers at most 45 offers across its hotels, and with it at most 100. Three hotels still get 15 each; more hotels get fewer each. See [the offers budget](/errors#offers-budget).
- **A search filters only by the nine amenity codes that can filter.** Any other code is `invalid_request`; the `filterable` and `share` details of that refusal are removed.
- **A search cursor from 5.x answers `cursor_invalid`.** Start again from the first page.

### New

- An order says why it failed: `failure` is `{ reason }` on every `failed` order, with `reason` `rate_unavailable`, `hotel_refused` or `unknown` (a reason not on record), and `null` on any other order.
- An order says what a cancellation kept and returned: `cancelled` is `{ at, penalty, refund }` on a `cancelled` order, and `null` otherwise.
- An order's hotel item has `confirmation`, how the hotel confirms the booking, as its offer gave it.
- Each room of an order has its own `roomType` and `meals`, so an order whose rooms differ shows every room.
- A search note can carry the facts its words need, as `details`: `area_absorbed` has `places`, the smaller places of the same name inside the searched area, and `locality_available` has `localityTotal`, how many matching hotels the locality has. `details` is optional on both.
- A fee payable at the property has a `kind`: `tax`, `resort_fee`, `other` or `unknown`.
- Each hotel of an offers answer has `omitted.byCallLimit`: how many more offers a call for that hotel alone would show.
- The error `client_outdated` (HTTP 426): a Fortrip CLI that is a major version behind the service is told to update, on its HTTP calls and through `fortrip mcp`. Other clients never get it. The CLI prints the message and exits 5, a code of its own, and sends `fortrip-cli/<version>` as its user agent through `fortrip mcp` too.
- `fortrip logout` forgets the sign-in on this machine even when Fortrip can't be reached or no longer takes this version of the CLI. It then answers `revoked: false` and warns that the sign-in was not revoked.
- `payment_method_unavailable` has `details.reason`: `payment_open_on_page`, `token_not_offered` or `charge_refused`.
- `invalid_request` names where a field belongs when a known field is sent at the wrong depth, such as `offerId` beside `items`; when the field is in its place too, it says to remove the copy, or, if the two differ, that two values were sent. A 5.x `contact.firstName` or `contact.lastName` is told that the contact takes one name.
- A guest name that the hotel's booking system would refuse answers `invalid_request` before an order is made, instead of an order that fails after payment.
- `offer_unavailable` says that other offers for the same room may be gone too.
- The MCP server's `serverInfo` has `title`, `description`, `websiteUrl` and `icons`.
- In a result's text, words Fortrip did not write never pass for its own. A short value someone else wrote (the name of a hotel, a room, a place or a guest, an address, the contact, special requests) is a JSON string in double quotes; a description or a policy is a quoted block under a label that says it is information from the hotel, not instructions. Ids, amounts, dates and links are bare, and only while they are written as such a value is; anything else in their place is quoted too. A hotel's website is shown only when it is an `http` or `https` URL.
- An order's text gives each next call whole: `cancel_order { orderId, maximumPenalty }` or `cancel_order { orderId, close: true }` on its Cancel line, and `pay_order { orderId, sharedPaymentToken, total }` on its "Pay without the link" line, with the order's own id, penalty and total (the CLI: the whole command). `order_not_cancellable` names its order in `details.orderId`, so its call is whole too.
- An offers answer echoes the request's `limitPerHotel`, `null` when it gave none, and its text says which limit cut a hotel's offers: the default, or the caller's.
- One optional part of an answer that doesn't parse (a search note's `details`, an order's `cancelled`, `failure` or `payment.tokenRequest`) no longer turns the whole text into a line of JSON: the part is read as absent.
- The rules for an answer are the last paragraphs of its text: how to present hotels, consent before a payment link, how to pay with a token, and consent before a cancellation. Tool descriptions say what a tool does and answers.

## 5.3.0

Released 2026-11-13.

An order shows who it is for, so the user can check the guests and the contact before paying.

### Added

- `contact` on an order (`book_hotel`, `get_order`, `list_orders`, `cancel_order`, `pay_order`, and `/v1/orders`): the contact's `name`, `email` and `phone` as given when ordering. It is null until an order started on the Fortrip website reaches checkout; `email` and `phone` are null when none is on record.
- `guests` on each of an order's `items[].hotel.rooms`: the guests named for that room, `firstName` and `lastName`; null when none are on record yet.
- `specialRequests` on an order's `items[].hotel`: the requests as given; null when none were given.
- The order text shows them as `Guests:`, `Special requests:` and `Contact:` lines.

### Changed

- The step before the payment link, and before paying with a token or with Alipay or WeChat Pay (`pay_order`), asks the agent to show each room's guests by name, the contact (name, email, phone) and any special requests too, as the order holds them. A wrong contact, like a wrong guest name, is corrected with a new order of a new offer. The Claude plugin's skill and the CLI skill say the same.

### Migration

- Nothing is required: a client that doesn't know the new fields ignores them.

## 5.2.0

Released 2026-11-10.

A search can suggest CNY, and the text that agents read is corrected and shorter.

### Added

- `currencyHint` on `search_hotels` (`POST /v1/hotels/search`): present only when the search isn't in CNY and the request comes from mainland China (`reason: "request_location"`) or the user's latest sign-in to Fortrip was there (`"sign_in_location"`). It says CNY prices are available too; the agent decides whether to offer them. The result text ends with the same suggestion.

### Changed

- `currency` on `search_hotels` and `get_hotel_offers` no longer lists payment methods, which can change: each currency is paid through its own channel, the order's payment page shows the methods, and CNY, paid through channels in mainland China, suits a user who pays that way. The Claude plugin's skill and the CLI skill say the same.
- `pay_order` says it pays USD orders, and that a shared payment token is only for an agent that can request one from the user's Link wallet.
- The Alipay and WeChat Pay step of an order says to send the order's total with the method (`--total` in the CLI).
- `cancel_order` states its own confirmation rule. `payment_total_changed` tells the CLI to rerun the same command with the order's total, for a token or a wallet payment.
- The MCP server instructions are shorter. Rules about a tool's data (guest names, what `price.total` covers, `offer_changed`, one party per call) are stated in that tool's description and inputs instead.

### Migration

- Nothing is required: `currencyHint` is optional, and a client that doesn't know it ignores it.

## 5.0.1

Released 2026-11-09.

The schemas keep their shape. The change is to the text that agents read.

### Changed

- `currency` on `search_hotels` and `get_hotel_offers` says to use `CNY` only for a user who pays with Alipay, WeChat Pay or a bank card from mainland China, the only ways a CNY order can be paid: when the user asks for CNY or says they pay that way. An agent asks only when the conversation suggests it, and otherwise keeps `USD`. The Claude plugin's skill and the CLI skill say the same.

## 5.0.0

Released 2026-11-09.

A major release. A request is priced and charged in one currency, USD or CNY, and `payment.methods` replaces the three payment fields.

### Breaking changes

- `displayCurrency` is now `currency` on `search_hotels` and `get_hotel_offers`. It sets the currency of every price in the answer and of the order made from the offers: a search in CNY gets offers in CNY, and the order is charged in CNY. The default is `USD`.
- `approx` is removed from search hits and offers. Prices are in the request's currency, not converted.
- Money in a request is in the request's or the order's currency, not always USD:
  - `filters.price.maxPerRoomNight` is in the search's `currency`. A different currency is `invalid_request`.
  - `total` on `pay_order` is the order's `price.total`, in its currency.
- `payment.handlers`, `payment.credentialLimits` and `payment.wallets` are removed. `payment.methods` lists what `pay_order` accepts for the order now, one entry per way, by `id`:
  - `payment.handlers` and `payment.credentialLimits` → the `stripe_shared_payment_token` entry, with `handler` and `limits { maxAmount, currency, expiresAt }`. The entry is absent where `handlers` was `[]`.
  - `payment.wallets` → the `stripe_alipay_wechat_pay` entry, with `open`, `current`, `wechatPay` and `alipay`. The entry is absent where `wallets` was `null`.
  - `[]` means: give the user `payment.url`.
- `pay_order`'s `method: "alipay_wechat_pay"` is now `method: "stripe_alipay_wechat_pay"`. A token is sent as before.
- `maximumPenalty` on `cancel_order` is Money, the order's `cancel.penalty` exactly as returned, in whatever currency it is, instead of a JSON number. It is optional: an unpaid order is closed without it.
- `get_planning_guide` is removed, and so is `fortrip guide`. The planning guide is a file in the Claude plugin and the CLI skill, `references/planning.md`.
- One offer is one order. Ordering the same offer again answers its order: the same details replay it, and other details answer `offer_already_ordered`, even when that order failed or expired. Another order of the stay, for another party or after an order failed or expired, takes a new offer and gets its own `orderId`. Nothing refuses a second open order of the same stay any more: when a new order replaces an unpaid one, have the user pay only the new link, or close the old order with `cancel_order`. The errors `order_exists`, `order_removed` and `order_attempts_exhausted` are removed: the server no longer answers them.
- CLI:
  - `--display-currency` is now `--currency`, and `FORTRIP_DISPLAY_CURRENCY` is now `FORTRIP_CURRENCY`.
  - `orders pay --wallet` is now `--method stripe_alipay_wechat_pay`.
  - `orders cancel --max-penalty` takes the amount as before, e.g. `12.50`; the CLI now reads the order for the currency, that of the order's `cancel.penalty`, else of its `price.total`. `orders pay --total` is likewise in the order's currency.
  - `--price-max-per-room-night` is in the search's `--currency`.

### New

- `cancel_order` closes an unpaid order. Such an order has `cancel.available` `true` with `cancel.reason` `unpaid`; `cancel_order` with the `orderId` alone makes it `expired`, and nothing is charged. A paid order is cancelled as before, with `maximumPenalty`.
- `orders cancel --close` closes an unpaid order. Exit codes:
  - 0: the order is closed, or was already `expired`.
  - 1: the order can't be closed, or was paid meanwhile.
  - 2: the order is paid (cancel it with `--max-penalty`), or `--close` is given with `--max-penalty`.
- `orders cancel --max-penalty` on an unpaid order cancels nothing and exits 2, as `orders cancel` with neither option does.
- `expired` also means an order that was closed.
- The error `currency_unavailable` (422), with `details { currency }`: prices in that currency aren't available. Offer the user USD.
- `payment.url` is `null` for an order awaiting payment only while its payment is `unpaid` and the link couldn't be read this time; read the order again. A held payment (`payment.status` `authorized`) has no link: the link stops working once a payment succeeds.
- The user pays on `payment.url`, a Fortrip page that continues to the payment provider: Stripe for a USD order, a cashier in China (Alipay, WeChat Pay or a Chinese bank card) for a CNY order. Or they pay by a way listed in `payment.methods`.
- A CNY order is charged in CNY: `payment.localCurrencyAtCheckout` is `false`, `payment.localCharge` is `null`, and `payment.methods` is empty, so it is paid only through `payment.url`. A token is charged in USD, and the cashier takes Alipay, WeChat Pay and Chinese bank cards itself.
- With `fortrip guide` gone, nothing pins the CLI version any more: the CLI skill runs `npx -y fortrip@latest`, as before.

### Migration

- Send `currency` instead of `displayCurrency`, and read every price in that currency without converting it. `approx` is gone.
- Send `filters.price.maxPerRoomNight` and `total` as Money in the search's and the order's currency.
- Send `maximumPenalty` as Money, the order's `cancel.penalty` exactly as returned.
- Read `payment.methods` instead of `payment.handlers`, `payment.credentialLimits` and `payment.wallets`, and send `method: "stripe_alipay_wechat_pay"` to open an Alipay or WeChat Pay payment.
- Handle `currency_unavailable`.
- `cancel.available` is also true for an unpaid order (`reason` `unpaid`, `penalty` null): check `reason`.
- Close an unpaid order with `cancel_order` when the user no longer wants it.
- Stop calling `get_planning_guide` and `fortrip guide`.
- Drop any handling of `order_exists`, `order_removed` and `order_attempts_exhausted`. To order a stay again, get offers again and order the new offer; when it replaces an unpaid order, close that one or tell the user to pay only the new link.
- Update the CLI to 5.0.0, and use `--currency`, `FORTRIP_CURRENCY` and `--method`. A 4.x CLI shows this server's searches, offers and orders only as raw JSON, and its cancel, Alipay or WeChat Pay and `--display-currency` requests are refused, as is its token payment of a CNY order.

### Package

- `usdMoney` is now `requestMoney(name)`: Money in USD or CNY, whose refusal names the field.
- `DISPLAY_CURRENCIES` is now `CURRENCIES`, with the type `Currency`.
- New: `PAYMENT_METHOD_IDS`, `paymentMethod`, and the types `PaymentMethod` and `PaymentMethodId`.
- The `PAY_WAYS` values are `payment_link`, `stripe_shared_payment_token` and `stripe_alipay_wechat_pay`.
- `RenderedTool` and `HttpToolName` are every tool name, `get_planning_guide` being removed.
- `UNKNOWN_IS_NOT_NO_EXEMPTIONS` keys `payment.handlers` and `payment.wallets.open` are now `payment.methods` and `payment.methods.open`.
- `LIMITS.ordersPerStay` is removed, and so are the three error codes, from `ErrorCode`, `ERROR_CODES` and `ERROR_DETAILS`.
- A Money a request sends (`requestMoney`, and `cancel_order`'s `maximumPenalty`) is typed as `Money` on input too: `CancelOrderInput`, `PayOrderInput` and `SearchHotelsInput` no longer have `unknown` for it.
- `ToolSpec.input` and `ToolSpec.output` are required, not `null`. `PositionalSpec.field` is a `string`, and `PositionalSpec.optional` and `FlagSpec.optional` are removed. The `guide` command is removed from `COMMANDS`.

## 4.0.0

Released 2026-11-04.

A major release. It removes what was kept for older clients, and makes required what the server always sends.

### Breaking changes

- `payment.handlers[].networkId` is removed. `schema`, `available_instruments` and `config { environment, business_profile }` are required.
- `payment.handlers` is always sent: `[]` when a token can't pay the order, with `payment.credentialLimits` `null`.
- `order.cancel` is always sent.
- A hotel's `photos` and a search hit's `photo` are always sent, `null` when there are none.
- Each error code's `details` is required where the code defines it. `search_too_broad`'s `details.center` is required and may be `null`.
- No token payment over $500, Link's cap per spend request. Such an order has empty `payment.handlers`, and `pay_order` answers `payment_method_unavailable` before anything is charged. Exactly $500 can still be paid by token.
- The API takes only an OAuth bearer token as the caller's identity. OAuth authorization-server metadata is served on `mcp.fortrip.ai` only.
- CLI:
  - With `--json`, a 429 without Fortrip's error envelope is reported as `service_unavailable`, retryable, instead of `rate_limited`. The exit code is still 4.
  - With `--json`, a local `invalid_request` always carries `details.issues`, empty for an error in the command line itself.

### New

- The hosted API and MCP server take the 3.5.0 additions: UCP's handler fields, and the token in `payment.instruments`.

### Migration

- Request the token with `config.business_profile` in place of `networkId`.
- Treat an empty `payment.handlers` as "no token payment", instead of checking whether the field is present.
- Update the CLI to 4.0.0. A 3.x CLI can't read the orders this server sends.

### Package

- `strictErrorEnvelope()` is removed: use `strictOutput(errorEnvelope)`.
