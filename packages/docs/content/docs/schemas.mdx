An MCP result has no JSON of its own: its text is written from these objects ([what a tool returns](/mcp#results)).

## Reading the tables [#reading]

- Every field is present unless marked optional; `| null` means the field can be `null`. On catalogue facts `null` means not known, never no. Elsewhere it has its own meaning: `nextCursor` is `null` on the last page, `payment.url` when there is no link to pay now, and `payment.tokenRequest` when no token can pay the order.
- `[]` marks the items of a list, and "when `kind`" or "when `type`" a branch of a union, with that branch's fields below it.
- Field rules shared by every response (ids, [money](/api#money), dates, names) are in [Conventions](/api#conventions), with how to read responses tolerantly.

## Names shared across objects [#names]

- **`total`** is what is charged for the whole stay and every room, on an offer and on an order. An offer's `perRoomNight` is for comparison only: it need not multiply back to `total`.
- **`roomType`** is one object on an offer, on each room of an order, and in a hotel's `roomTypes`. Nothing joins an offer's `roomType` to an entry of a hotel's `roomTypes`: the names can differ, so don't match them.
- **`cancellation`**, **`confirmation`** and **`payAtProperty`** hold for the whole stay, on an offer and on an order's hotel item. `meals` and `roomType` hold per room: an offer has one of each for all its rooms, and an order has them on each entry of `rooms`.
